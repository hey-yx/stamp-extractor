# 提取算法说明

实现都在 `extract.js`，入口 `SealExtract.processImageData(imageData, options)`。

## 1. 工作尺寸

最长边限制 1800px。原图更大时等比缩小，后面的裁切范围也按缩小后的尺寸算。章在 300 到 600px 时效果最好，再大不会增加细节。

## 2. 红色分值

对每个像素算一个「有多红」的分值：

```
score = (R - (G+B)/2) / (R + G + B + 1)
```

白纸和黑字都接近 0，红墨明显为正。这个比值对光线亮暗不敏感，同一枚章在偏亮和偏暗的扫描里得分接近。

## 3. 自动校色

只校纸色：取最亮的 20% 像素当作纸面，把纸面拉回白色，每种颜色的放大倍数限制在 0.75 到 1.35。增强开启时门槛再乘 0.92，淡墨更容易留下。

不做整体提亮压暗。试过：白底红章的图里，红墨亮度落在最暗的 1% 附近，整体提亮会把红色通道压到 0，整枚章变黑，分值直接归零。这类操作会拉偏颜色比例，对提取是负作用。

也不直接把颜色加浓：`c' = L + (c-L)*1.3` 会让边缘混纸的浅红也过线，笔画普遍粗 1px，小字容易粘连。

## 4. 门槛

```
sensitivity 50 → 0.105
0 → 0.20
100 → 0.054
```

映射是 `0.105 * 0.72^((s-50)/25)`。默认 50，再乘增强系数 0.92，实际 0.0966。

一条门槛就够，不用两条。测试里红墨和纸面的分值分成两堆，中间几乎没有像素；再加一条 0.55 倍的弱门槛没补回任何像素，反而多跑一遍全图搜索。

## 5. 拼块与主章

1. 把过线的像素连成块，上下左右挨着就算同一块，丢掉面积小于 `图面积 × 1e-5` 的碎点。
2. 以最大的块为主章，把外框相距不到短边 4% 的块并进来。章的细线条经常被黑字或断墨切成几段，这一步把同一枚章重新拼齐；远处红色标题、logo 相距更远，不会并进来。
3. 只留拼好的主章，其余清掉。

试过先把细缝补上再找主章：补缝会把细笔画撑粗、吃掉字间空隙，小字明显变糊。现在不补缝。

## 6. 裁切与透明

按章体实际范围裁切，只留 1px 透明边，输出尺寸等于章体实际像素，不扩成方形、不加留白。章以外全部透明，没有半透明像素，边缘不做模糊。

## 7. 颜色

- 纯红 `#FF0000`：默认，屏幕纯红。国家标准只要求「印章用红色」，没有给色值。
- 标准红 `#DA251D`：取深圳市地方标准 DB4403/T 383.6-2023 第 5.3 条的印模色 RGB(218, 37, 29)。

## 8. 性能

用户的 1280×582 照片，工作尺寸不缩放，处理约 60 到 120ms（不含页面合成预览）。1800×1800 的图约 300ms。时间主要花在拼块和导出画布上。
